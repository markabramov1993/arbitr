The transfer API is explicitly two-phase. A successful payout request can return a phase of pending, a pending ID, a transaction hash, and a confirmation window. The current payout script deliberately describes that state as queued, not settled. That wording matters. During the pending period, the balance has not necessarily moved yet. A contributor should not count the reward as spendable merely because the payout request returned HTTP two hundred. RustChain's own API example shows a transfer-pending response with a twenty-four-hour confirmation window.
